⏸️ Task 1. Create a discovery scan configuration for BigQuery in paused mode

ℹ️ Task ini dikerjakan secara manual melalui Google Cloud Console.

🛠️ Panduan Langkah Manual di Console:

  1. Di Google Cloud Console, klik Navigation menu (☰) > Security > Sensitive Data Protection.
  2. Pilih tab Discovery.
  3. Di bawah opsi BigQuery, klik Enable.
  4. Untuk Select a discovery type, biarkan opsi BigQuery tercentang, lalu klik Continue.
  5. Untuk Select scope, biarkan opsi Scan selected project, lalu klik Continue.
  6. Untuk Managed schedules, biarkan default, lalu klik Continue.
  7. Untuk Select inspection template, biarkan opsi Create new inspection template tercentang, lalu klik Continue.
  8. Pada bagian Add actions:
    • Aktifkan (Centang) Publish to Security Command Center.
    • Aktifkan (Centang) Save data profile copies to BigQuery. Isikan parameter berikut:
      • Dataset ID: bq_discovery
      • Table ID: data_profiles
  9. Biarkan default lainnya, lalu klik Continue.
  10. Untuk Set location to store configuration, biarkan terpilih us (multiple regions in United States), lalu klik Continue.
  11. Isikan Display Name: BigQuery Discovery
    ⚠️ Pastikan tidak ada spasi tidak sengaja di awal atau akhir nama!
  12. Aktifkan/Centang opsi Create scan in paused mode.
  13. Klik Create, lalu konfirmasi dengan mengklik Create configuration.
💡 Tips Progres: Setelah mengklik tombol Create configuration, kamu bisa langsung lanjut mengerjakan Task 2 tanpa perlu menunggu lama. Cek tombol Check my progress pada Task 1 selagi menyiapkan Task 2.
🔍 Penjelasan Langkah & Konsep (Task 1)
  • Sensitive Data Protection Discovery: Layanan terkelola Google Cloud yang secara otomatis memindai aset BigQuery untuk mengidentifikasi keberadaan informasi sensitif (seperti infoType Nomor KTP/SSN, Email, Nama) dan tingkat risiko data.
  • Data Profiles ke BigQuery: Menyimpan hasil ringkasan dan metadata profil pemindaian secara langsung ke dataset BigQuery (bq_discovery.data_profiles) agar dapat dianalisis ulang atau divisualisasikan.

🏷️ Task 2. Create tags and grant role for automated tagging during discovery scan

Membuat Resource Tags sensitivitas data di Console IAM, serta memberikan izin IAM ke Service Account DLP via Cloud Shell.

🛠️ Langkah 1: Buat Sensitivity Level Tag di Console IAM

  1. Buka Navigation menu (☰) > IAM & Admin > Tags.
  2. Klik + Create.
  3. Isi Tag key: sensitivity-level
  4. Isi Tag description: Sensitivity level tagged as low, moderate, high, and unknown
  5. Klik + Add value dan masukkan 4 Tag Values berikut satu per satu:
    Tag value Tag description
    low Tag value to attach to low-sensitivity data
    moderate Tag value to attach to moderate-sensitivity data
    high Tag value to attach to high-sensitivity data
    unknown Tag value to attach to resources with an unknown sensitivity level
  6. Klik Create tag key dan tunggu proses pembuatan selesai.

🛠️ Langkah 2: Grant Role ke Service Account DLP via Cloud Shell
Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell:

🔍 Penjelasan Langkah & Konsep (Task 2)
  • Resource Tags (IAM Tags): Kunci & Nilai (Key/Value) terpusat pada tingkat organisasi/project GCP yang digunakan untuk mengontrol tata kelola data dan kebijakan akses secara dinamis.
  • roles/resourcemanager.tagUser: Peran IAM yang wajib diberikan kepada Service Agent bawaan DLP (service-$PROJECT_NUMBER@dlp-api.iam.gserviceaccount.com) agar pemindaian otomatis dapat menempelkan tag tingkat sensitivitas ke aset terkait.

▶️ Task 3. Update the paused discovery scan with automated tagging and start scan

ℹ️ Task ini dikerjakan secara manual melalui Google Cloud Console.

🛠️ Panduan Langkah Manual di Console:

  1. Kembali ke menu Sensitive Data Protection > tab Discovery > tab Scan Configurations.
  2. Cari baris bernama BigQuery Discovery, klik ikon titik tiga (⋮) di sebelah kanan, lalu pilih Edit.
  3. Di bawah bagian Add actions, aktifkan/centang opsi Tag resources.
  4. Aktifkan keempat opsi pemetaan tag dan isikan nilainya sesuai path berikut:
    • Tag high sensitivity resources: <PROJECT_ID>/sensitivity-level/high
    • Tag moderate sensitivity resources: <PROJECT_ID>/sensitivity-level/moderate
    • Tag low sensitivity resources: <PROJECT_ID>/sensitivity-level/low
    • Tag unknown sensitivity resources: <PROJECT_ID>/sensitivity-level/unknown
  5. Centang juga 2 opsi berikut:
    • When a tag is applied to a resource, lower the data risk of its profile to LOW.
    • Tag a resource when it is profiled for the first time.
  6. Klik Save, lalu klik Confirm edit.
  7. Terakhir, klik tombol Resume Scan untuk memulai proses pemindaian discovery secara aktif.
⚠️ Proses Pemindaian Latar Belakang: Setelah menekan Resume Scan, engine pemindaian SDP akan bekerja secara asinkron. Kamu bisa langsung mengklik Check my progress pada Task 3 tanpa harus menunggu pemindaian selesai seluruhnya.
🔍 Penjelasan Langkah & Konsep (Task 3)
  • Automated Tagging: SDP Discovery akan melabeli tabel/dataset BigQuery secara otomatis berdasarkan kategori temuan infoType terdeteksi (seperti menandai high jika ditemukan SSN/KTP).
  • Resume Scan: Mengubah status konfigurasi pemindaian dari terhenti (Paused) menjadi aktif (Active).

🔐 Task 4. Explore conditional access for BigQuery using tags

ℹ️ Task ini dikerjakan secara manual melalui Google Cloud Console (Menggunakan Shortcut Video!).

💡 Shortcut Pengerjaan Cepat (Sesuai Video Tutorial): Kamu TIDAK PERLU logout dan login ulang sebagai Username 2. Seluruh pengaturan IAM dan penempelan Tag pada dataset BigQuery dapat dikerjakan secara langsung menggunakan akun utama (Username 1).

🛠️ Langkah 1: Update IAM Roles untuk Username 2

  1. Buka Navigation menu (☰) > IAM & Admin > IAM (Tetap login sebagai Username 1).
  2. Cari baris untuk Username 2: <EMAIL_USER_2>, lalu klik ikon pensil (Edit principal).
  3. Cari peran Viewer, lalu klik ikon tempat sampah (Delete role).
  4. Klik Add another role, pilih Basic > Browser.
  5. Cari peran BigQuery Data Viewer, lalu klik tombol Add IAM condition.
  6. Isikan konfigurasi Condition:
    • Title: Low Sensitivity Data Access Only
    • Condition builder: Pilih Tag untuk Condition type 1, dan pilih has value untuk Operator.
    • Value path: <PROJECT_ID>/sensitivity-level/low
  7. Klik Save, lalu klik Save lagi pada panel IAM utama.

🛠️ Langkah 2: Tempelkan Low Sensitivity Tag ke Dataset BigQuery

  1. Buka Navigation menu (☰) > BigQuery.
  2. Di panel Explorer sebelah kiri, luaskan ID Project: <PROJECT_ID>.
  3. Klik dataset bernama damaged_car_image_info.
  4. Di panel sebelah kanan, klik Edit details (ikon pensil).
  5. Pada bagian Tags, klik Select scope > Select current project.
  6. Pilih atribut berikut:
    • Key 1: sensitivity-level
    • Value 1: low
  7. Klik Save.
✅ Setelah menyelesaikan kedua langkah di atas, kamu dapat langsung mengklik tombol Check my progress pada Task 4 tanpa perlu berpindah browser/sesi login!
🔍 Penjelasan Langkah & Konsep (Task 4)
  • Attribute-Based Access Control (ABAC) via Resource Tags: Membatasi hak akses BigQuery Data Viewer hanya pada dataset/tabel yang dilabeli tag `low`. Dataset berisi data sensitif (seperti `car_buyers`) yang tidak bertag `low` secara otomatis tersembunyi dari Username 2.
