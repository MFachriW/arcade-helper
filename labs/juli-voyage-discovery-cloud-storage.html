🔍 Task 1: Enable Discovery for Continuous Monitoring of Cloud Storage

💻 Task ini diselesaikan secara manual melalui Google Cloud Console UI.

🛠️ Panduan Langkah Manual di Cloud Console:

  1. Buka Google Cloud Console. Di Navigation menu (☰), pilih Security > Sensitive Data Protection (di bawah bagian Data Protection).
  2. Pilih tab Discovery. Pada bagian Cloud Storage, klik Enable.
  3. Untuk Select a discovery type, biarkan opsi Cloud Storage aktif, lalu klik Continue.
  4. Untuk Select scope, biarkan Scan selected project aktif, lalu klik Continue.
  5. Untuk Managed schedules, biarkan default, lalu klik Continue.
  6. Untuk Select inspection template, biarkan Create a new inspection template aktif, lalu klik Continue.
  7. Pada bagian Add actions:
    • Aktifkan Publish to Security Command Center.
    • Aktifkan Save data profile copies to BigQuery. Isikan parameter berikut:
      • Project ID: <PROJECT_ID>
      • Dataset ID: cloudstorage_discovery
      • Table ID: data_profiles
  8. Klik Continue.
  9. Untuk Set fallback processing locations, biarkan default, lalu klik Continue.
  10. Untuk Set location to store configuration, biarkan us (multiple regions in United States) aktif, lalu klik Continue.
  11. Isikan Display name: Cloud Storage Discovery
  12. Klik Create, lalu konfirmasi dengan mengklik Create configuration.
  13. Masuk ke tab Profiles. Pilih Location type: Region > Region.
  14. Klik tab File Stores pada tabel Data Profiles. Setelah tampilan memuat, kamu bisa langsung menekan tombol Check my progress di portal Qwiklabs.
🔍 Penjelasan Langkah & Konsep (Task 1)
  • Discovery Service: Fitur pemindaian otomatis Sensitive Data Protection yang mengidentifikasi lokasi data sensitif/berrisiko tinggi di seluruh Cloud Storage bucket organisasi secara kontinu.
  • Data Profiles: Ringkasan wawasan mengenai tipe data sensitif (infoTypes) serta level sensitivitas dan risiko data yang terdeteksi.
  • BigQuery Export: Menyimpan salinan profil data ke tabel BigQuery (cloudstorage_discovery.data_profiles) agar dapat dianalisis lebih lanjut via SQL atau visualisasi Looker Studio.

🛠️ Task 2: Create and Modify Reusable Templates for Inspecting and Redacting Specific infoTypes

💻 Task ini diselesaikan secara manual melalui Google Cloud Console UI.

🛠️ Panduan Langkah Manual di Cloud Console:

A. Modify Existing Inspection Template:

  1. Navigasi ke Sensitive Data Protection > tab Configuration > tab Templates.
  2. Cari template yang otomatis dibuat oleh discovery di Task 1 (Catat ID template tersebut, misal 7216194786087173213 dan masukkan ke form input atas).
  3. Klik titik tiga vertikal (⋮) pada kolom Actions untuk ID template tersebut, lalu pilih Edit.
  4. Ubah Display name menjadi: Inspection Template for US SSN
  5. Ubah Description menjadi: This template was created as part of a Sensitive Data Protection profiler configuration and was modified for deeper inspection for US Social Security numbers.
  6. Pada InfoTypes, klik Manage InfoTypes.
    • Centang hanya US_SOCIAL_SECURITY_NUMBER dan hapus centang pada opsi lainnya. (Tips: Klik Select all rows dua kali untuk dengan cepat menghapus centang semua).
    • Klik Done.
  7. Untuk Confidence threshold ("minimum likelihood"), pilih Unlikely.
  8. Biarkan default lainnya, klik Save, lalu klik Confirm save.

B. Create a De-identify Template for Structured Data:

  1. Masih di tab Templates, klik Create Template.
  2. Isikan nilai berikut:
    • Template type: De-identify (remove sensitive data)
    • Data transformation type: Record
    • Template ID: us_ssn_deidentify
    • Display name: De-identification Template for US SSN
    • Location type: Multi_region > global (Global)
  3. Klik Continue.
  4. Pada Configure de-identification > Transformation Rule #1:
    • Field names: Ketik ssn lalu tekan Enter, ketik email lalu tekan Enter.
    • Transformation type: Primitive field transformation.
    • Transformation method > Transformation: Replace.
    • Replace type: String.
    • String value: Biarkan default [redacted].
  5. Klik + Add Transformation Rule untuk menambah aturan kedua:
    • Field name: Ketik message lalu tekan Enter.
    • Transformation type: Match on infoType, lalu klik Add Transformation.
    • Transformation Method: Replace with infoType name.
    • InfoTypes to transform: Any detected infoTypes defined in an inspection template or inspect config that are not specified in other rules.
  6. Klik Create. Jika langkah A dan B selesai, kamu bisa menekan tombol Check my progress di Qwiklabs.
🔍 Penjelasan Langkah & Konsep (Task 2)
  • Inspection Template: Konfigurasi terintegrasi yang mendefinisikan apa yang harus dicari (infoTypes) dan seberapa yakin algoritma sebelum menandainya sebagai temuan sensitif (likelihood threshold).
  • De-identification Template: Konfigurasi aturan transformasi untuk menyamarkan/meredaksi data sensitif (seperti mengganti string dengan [redacted] atau menimpa dengan nama infoType).

📊 Task 3: Review Initial Discovery Results

💻 Task ini berupa tinjauan visual dashboard dan IAM permissions pada Google Cloud Console.

📖 Alur Tinjauan Dashboard & IAM:

  1. Di Sensitive Data Protection > tab Discovery > Scan Configurations, cari baris Cloud Storage Discovery.
  2. Di kolom Data Studio, klik link Looker.
  3. Berikan otorisasi Looker Studio (Authorize -> Akun <PROJECT_ID> / Username 1 -> Acknowledge -> Allow).
  4. Tinjau ringkasan di tab Summary Overview dan Advanced Exploration (Asset Details).
  5. Kembali ke Console Sensitive Data Protection untuk melihat detail IAM Permissions pada Cloud Storage profile details, perhatikan pengguna <EMAIL_USER_2> terdaftar sebagai Storage Admin.
💡 Mengapa Kita Meninjau Hasil Discovery? (Task 3)
  • Dashboard Looker memberi visibilitas cepat mengenai persebaran tipe data berrisiko (misal: keberadaan US_SOCIAL_SECURITY_NUMBER) di bucket storage.
  • Pemeriksaan IAM memastikan kita mengetahui siapa saja akun pengguna yang memiliki wewenang penuh (seperti Storage Admin) terhadap data mentah sensitif tersebut.

🔎 Task 4: Create and Run an Inspection Job

💻 Task ini diselesaikan secara manual melalui Google Cloud Console UI.

🛠️ Panduan Langkah Manual di Cloud Console:

  1. Buka menu Sensitive Data Protection > tab Inspection. Klik Create job and job triggers.
  2. Pada Choose input data, isikan:
    • Job ID: us_ssn_inspection
    • Location type: Multi_region > us (multiple regions in United States)
    • Storage type: Google Cloud Storage
    • Location type: Scan a single file or folder path
    • URL: gs://<PROJECT_ID>-input/ (Pastikan ada garis miring / di akhir!)
    • Scan recursively: Enable / Centang
    • Sampling: Naikkan menjadi 100%
    • Sampling method: No sampling
    • Files: Pilih hanya TEXT dan CSV (hapus centang opsi lainnya), lalu klik OK.
  3. Klik Continue.
  4. Pada Inspection template > Template name, masukkan path template yang telah kamu sesuaikan:
    projects/<PROJECT_ID>/locations/global/inspectTemplates/<TEMPLATE_ID>
    (Pastikan tidak ada spasi tambahan!)
  5. Klik Continue.
  6. Pada Add actions:
    • Aktifkan Save to BigQuery dan centang Include quote.
    • Isikan BigQuery destination:
      • Project ID: <PROJECT_ID>
      • Dataset ID: cloudstorage_inspection
      • Table ID: us_ssn
    • Aktifkan juga Publish to Security Command Center.
  7. Klik Continue. Biarkan Schedule sebagai None.
  8. Klik Create, lalu konfirmasi dengan mengklik Confirm create.
  9. Tunggu hingga status job berubah menjadi Done. Setelah status Done, klik Check my progress di Qwiklabs.
🔍 Penjelasan Langkah & Konsep (Task 4)
  • Inspection Job: Proses pemindaian terarah (deep inspection) pada jalur direktori tertentu menggunakan kriteria dari inspection template yang spesifik.
  • Include Quote & BigQuery Export: Opsi ini menyimpan teks kutipan persis (quote) yang teridentifikasi sebagai data sensitif beserta lokasi filenya ke dalam tabel BigQuery untuk auditibilitas penuh.

🛡️ Task 5: Create and Run a De-identify Job

💻 Task ini diselesaikan secara manual melalui Google Cloud Console UI.

⚠️ Perhatian: Job De-identification memproses pembuatan salinan berkas baru di Cloud Storage. Tunggu hingga status job di Console berubah menjadi Done (membutuhkan waktu sekitar 1 - 3 menit) sebelum menekan tombol Check my progress.

🛠️ Panduan Langkah Manual di Cloud Console:

  1. Buka menu Sensitive Data Protection > tab Inspection. Klik Create job and job triggers.
  2. Pada Choose input data, isikan:
    • Job ID: us_ssn_deidentify
    • Location type: Multi_region > us (multiple regions in United States)
    • Storage type: Google Cloud Storage
    • Location type: Scan a bucket with optional include/exclude rules
    • Bucket name: <PROJECT_ID>-input (Tanpa spasi & tanpa garis miring di akhir)
    • Sampling: Naikkan menjadi 100%
    • Sampling method: No sampling
    • Files: Pilih hanya TEXT dan CSV (hapus centang opsi lainnya), lalu klik OK.
    • Pada Exclude paths, klik Add exclude regex, lalu ketik: ignore (menjadi: gs://<PROJECT_ID>-input/ignore).
  3. Klik Continue. Pada Configure detection, biarkan default dan klik Continue.
  4. Pada Add actions, gulir ke bawah dan aktifkan Make a de-identified copy.
    • Structured de-identification template:
      projects/<PROJECT_ID>/locations/global/deidentifyTemplates/us_ssn_deidentify
    • Aktifkan Export transformation details to BigQuery:
      • Project ID: <PROJECT_ID>
      • Dataset ID: cloudstorage_transformations
      • Table ID: deidentify_ssn_csv
    • Cloud Storage output location: gs://<PROJECT_ID>-output
    • Files: Pilih hanya TEXT dan CSV, lalu klik OK.
  5. Klik Continue. Biarkan Schedule sebagai None.
  6. Klik Create, lalu klik Confirm create.
  7. Tunggu hingga status job berubah menjadi Done, lalu klik Check my progress di Qwiklabs.
🔍 Penjelasan Langkah & Konsep (Task 5)
  • De-identification Job: Eksekusi penyamaran/redaksi data sensitif yang menghasilkan berkas salinan baru yang aman di bucket tujuan (gs://[PROJECT_ID]-output). Berkas ini aman dibagikan ke tim analisis tanpa merusak integritas data asli.
  • Transformation Details: Menyimpan riwayat serta metadata baris mana saja yang telah diubah ke BigQuery untuk pelacakan audit.
