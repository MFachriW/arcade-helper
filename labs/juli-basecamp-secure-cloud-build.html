Secure Builds with Cloud Build

Panduan langkah demi langkah membangun kontainer aman, integrasi Artifact Registry, On-Demand Vulnerability Scanning, serta penerapan Security Gate dalam pipeline CI/CD.

Referensi & Pelajari Lebih Lanjut: Materi resmi lab ini diambil dari Google Cloud Skills Boost: Secure Builds with Cloud Build (Lab Official).

Task 1. Build images with Cloud Build
Task 1

Pada tugas ini, Anda akan memberikan hak akses Service Account Cloud Build, membuat direktori kerja, menyiapkan file aplikasi Python Flask sederhana beserta Dockerfile, dan menjalankan build pertama.

Penjelasan Teknis & Arsitektur
  • IAM Binding: Memberikan peran roles/ondemandscanning.admin ke Service Account Cloud Build agar pipeline otomatis dapat melakukan pemindaian kerentanan On-Demand.
  • Debian 11 Base Image: Dockerfile sengaja menggunakan base image lama (debian11) dan versi Flask 1.1.4 yang diketahui memiliki kerentanan tingkat tinggi/kritis untuk keperluan simulasi keamanan.

Task 2. Use Artifact Registry for Containers
Task 2

Buat repositori Docker di Artifact Registry region us-central1, konfigurasi otentikasi Docker CLI, lalu perbarui file pipeline cloudbuild.yaml untuk melakukan push image hasil build ke repositori tersebut.

Penjelasan Teknis

Artifact Registry merupakan repositori manajemen package dan image modern Google Cloud yang menggantikan Container Registry (gcr.io). Repositori ini memiliki fitur integrasi pemindaian kerentanan otomatis secara bawaan saat image di-push.

Task 3. Automated Vulnerability Scanning
Task 3

Pemindaian kerentanan otomatis (Automatic Scanning) diaktifkan secara default saat image di-push ke Artifact Registry.

Langkah Peninjauan di Google Cloud Console (Langkah Manual UI)
  1. Buka menu Artifact Registry di Google Cloud Console.
  2. Klik repositori artifact-scanning-repo.
  3. Klik nama image sample-image lalu pilih digest/tag terbaru.
  4. Buka tab Vulnerabilities untuk melihat daftar kerentanan yang terdeteksi secara otomatis oleh sistem.
Task 4. On Demand Scanning
Task 4

Lakukan pemindaian kerentanan secara lokal/on-demand sebelum melakukan push image ke repositori pusat. Perintah ini akan menganalisis image dan mengevaluasi apakah ditemukan kerentanan tingkat CRITICAL.

Penjelasan Teknis On-Demand Scanning

On-Demand Scanning memungkinkan pengembang memeriksa keamanan container image secara lokal di mesin pengembangan atau Cloud Shell sebelum dipublikasikan. Hasil pemindaian disimpan sementara di server metadata Google Cloud.

Task 5. Use Artifact Scanning in CI/CD & Fix Vulnerability
Task 5

Integrasikan pemindaian kerentanan sebagai Quality Gate di pipeline CI/CD Cloud Build. Jika kerentanan tingkat CRITICAL terdeteksi, build akan dibatalkan otomatis (Failed). Setelah itu, perbaiki Dockerfile agar build berhasil.

Penjelasan Integrasi CI/CD & Security Gate

Langkah ini mensimulasikan praktik terbaik DevSecOps (Shift-Left Security):

  • Langkah A (Simulasi Failure): Pipeline melakukan build, scan, dan memeriksa severity. Karena ditemukan kerentanan CRITICAL, perintah exit 1 dipanggil sehingga Cloud Build bernilai FAILED.
  • Langkah B (Remediasi): Kita memperbarui Dockerfile menggunakan base image ringan dan aman (python:3.12-alpine) serta pustaka versi terbaru, sehingga build ulang menghasilkan status SUCCESS.
