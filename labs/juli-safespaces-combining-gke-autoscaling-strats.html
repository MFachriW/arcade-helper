Task 1. Scale pods with Horizontal Pod Autoscaling

HPA (Horizontal Pod Autoscaler) akan secara otomatis menambah atau mengurangi jumlah pod berdasarkan penggunaan CPU.

Konsep HPA

Perintah autoscale di bawah akan menjaga rata-rata penggunaan CPU pada 50%. Jika beban naik melebihi 50%, HPA akan menambah pod (maksimal 10). Jika beban turun, HPA akan mengurangi pod (minimal 1).

Langkah 5.2: Terapkan Pod Disruption Budgets (PDB)

Kenapa butuh PDB?

Secara default, pod sistem (seperti kube-dns, metrics-server) mencegah Cluster Autoscaler untuk menghapus node tempat mereka berjalan. Dengan menerapkan PDB, kita mengizinkan Kubernetes untuk memindahkan pod-pod tersebut dengan aman sehingga node yang kosong bisa dihapus/dikecilkan skalanya.

Task 7. Test with larger demand

Sekarang kita akan memberikan beban palsu (load test) untuk melihat bagaimana HPA, Cluster Autoscaler, dan NAP bekerja sama menangani lonjakan trafik.

LANGKAH MANUAL PENTING:
  1. Buka tab Cloud Shell baru dengan mengklik ikon (+) (Add a Cloud Shell) di bagian atas terminal.
  2. Salin dan jalankan kode di bawah ini pada tab baru tersebut. Perintah ini akan berjalan terus-menerus (infinite loop).
  3. Biarkan tab tersebut berjalan, lalu kembali ke tab Cloud Shell pertama Anda untuk memantau hasilnya menggunakan perintah kubectl get hpa.
Jalankan di Tab Cloud Shell KEDUA (+)
⏳ Tunggu 1-3 Menit: Setelah menjalankan load test, pantau terus `kubectl get hpa` di tab pertama Anda. Tunggu sampai kolom target menunjukkan CPU di atas 100% dan pod mulai bertambah.

Setelah Anda melihat HPA merespons beban, Anda bisa kembali ke tab kedua dan menekan Ctrl + C untuk menghentikan load test.

Task 8. Optimize larger loads

Untuk menghindari waktu tunggu (latency) yang lama saat Cluster Autoscaler membuat node baru, kita dapat menggunakan strategi Pause Pods (Overprovisioning).

Konsep Pause Pods

Pause Pod adalah pod dengan prioritas sangat rendah yang tidak melakukan apa-apa selain memesan (reserve) ruang di node. Saat aplikasi utama membutuhkan ruang secara mendadak, Kubernetes akan menendang (evict) Pause Pod ini dan langsung memasukkan pod aplikasi utama, sehingga aplikasi tidak perlu menunggu node baru selesai dibuat.
