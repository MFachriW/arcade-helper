Persiapan & Instalasi Terraform di Cloud Shell

Secara bawaan, CLI Terraform belum terpasang secara permanen di lingkungan Cloud Shell. Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell untuk mengonfigurasi repositori HashiCorp dan memasang Terraform:

Bash (Cloud Shell) 
cat <<'EOF' > ~/.customize_environment
# Set up HashiCorp repository and install Terraform
wget -O - https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(grep -oP '(?<=UBUNTU_CODENAME=).*' /etc/os-release || lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install -y terraform
EOF
bash ~/.customize_environment

Verifikasi bahwa instalasi Terraform telah berhasil dengan mengeksekusi perintah:

Bash (Cloud Shell) 
terraform --version

Task 1. Menggunakan Modul dari Terraform Registry
Catatan Praktik Terbaik Video: Memanggil modul publik dari Registry mengharuskan argumen source dan disarankan menetapkan version secara eksplisit agar versi infrastruktur Anda stabil dan tidak pecah akibat pembaruan otomatis di kemudian hari.

Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell untuk mengkloning repositori contoh VPC Network Google dan mengalihkan *branch* ke versi v6.0.1:

Bash (Cloud Shell) 
git clone https://github.com/terraform-google-modules/terraform-google-network
cd terraform-google-network
git checkout tags/v6.0.1 -b v6.0.1

Selanjutnya, perbarui berkas variabel variables.tf pada direktori contoh proyek dengan menyetel Project ID default Anda (<PROJECT_ID>) dan nama jaringan example-vpc:

⚠️ Penting: Sebelum menyalin kode di bawah, pastikan parameter Project ID dan Region di atas sudah Anda isi agar nilainya terisi secara dinamis (tidak lagi berupa placeholder <PROJECT_ID> dan <REGION>).
Bash (Cloud Shell) 
cat <<'EOF' > ~/terraform-google-network/examples/simple_project/variables.tf
variable "project_id" {
  description = "The project ID to host the network in"
  default     = ""
}

variable "network_name" {
  description = "The name of the network to be created"
  default     = "example-vpc"
}
EOF

Perbarui konfigurasi utama main.tf pada direktori contoh proyek agar menggunakan variabel var.network_name serta menetapkan region subnet ke <REGION>:

Bash (Cloud Shell) 
cat <<'EOF' > ~/terraform-google-network/examples/simple_project/main.tf
module "test-vpc-module" {
  source       = "terraform-google-modules/network/google"
  version      = "~> 6.0"
  project_id   = var.project_id
  network_name = var.network_name
  mtu          = 1460

  subnets = [
    {
      subnet_name   = "subnet-01"
      subnet_ip     = "10.10.10.0/24"
      subnet_region = ""
    },
    {
      subnet_name           = "subnet-02"
      subnet_ip             = "10.10.20.0/24"
      subnet_region         = ""
      subnet_private_access = "true"
      subnet_flow_logs      = "true"
    },
    {
      subnet_name               = "subnet-03"
      subnet_ip                 = "10.10.30.0/24"
      subnet_region             = ""
      subnet_flow_logs          = "true"
      subnet_flow_logs_interval = "INTERVAL_10_MIN"
      subnet_flow_logs_sampling = 0.7
      subnet_flow_logs_metadata = "INCLUDE_ALL_METADATA"
      subnet_flow_logs_filter   = "false"
    }
  ]
}
EOF

Jalankan inisialisasi Terraform dan terapkan konfigurasi pembuatan jaringan VPC tersebut:

Bash (Cloud Shell) 
cd ~/terraform-google-network/examples/simple_project
terraform init
terraform apply -auto-approve
Penjelasan Konsep: Bagaimana Modul Registry Bekerja?

Saat Anda menjalankan perintah terraform init, Terraform secara otomatis mengunduh modul eksternal yang didefinisikan dalam blok module dari Terraform Registry ke dalam direktori tersembunyi .terraform/modules/.

  • Root Module: Direktori tempat Anda mengeksekusi perintah Terraform (dalam hal ini simple_project).
  • Child Module: Modul terraform-google-modules/network/google yang dipanggil dari luar.
  • Outputs: Nilai seperti nama jaringan dan range IP subnet dikembalikan oleh modul dan dapat dibaca melalui berkas outputs.tf.

Setelah progres Task 1 diverifikasi di Qwiklabs, bersihkan infrastruktur VPC ini sebelum melangkah ke Task 2:

Bash (Cloud Shell) 
terraform destroy -auto-approve
cd ~
rm -rf terraform-google-network
2
Task 2. Membangun Modul Kustom Sendiri

Pada tugas ini, Anda akan membuat modul kustom Terraform lokal untuk mengelola bucket Cloud Storage yang siap digunakan sebagai host situs web statis.

Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell untuk menyiapkan struktur direktori modul lokal:

Bash (Cloud Shell) 
cd ~
touch main.tf outputs.tf variables.tf
mkdir -p modules/gcs-static-website-bucket
cd modules/gcs-static-website-bucket
touch website.tf variables.tf outputs.tf

Isi konfigurasi resource Cloud Storage bucket pada website.tf di dalam direktori modul:

Bash (Cloud Shell) 
cat <<'EOF' > website.tf
resource "google_storage_bucket" "bucket" {
  name               = var.name
  project            = var.project_id
  location           = var.location
  storage_class      = var.storage_class
  labels             = var.labels
  force_destroy      = var.force_destroy
  uniform_bucket_level_access = true

  versioning {
    enabled = var.versioning
  }

  dynamic "retention_policy" {
    for_each = var.retention_policy == null ? [] : [var.retention_policy]
    content {
      is_locked        = var.retention_policy.is_locked
      retention_period = var.retention_policy.retention_period
    }
  }

  dynamic "encryption" {
    for_each = var.encryption == null ? [] : [var.encryption]
    content {
      default_kms_key_name = var.encryption.default_kms_key_name
    }
  }

  dynamic "lifecycle_rule" {
    for_each = var.lifecycle_rules
    content {
      action {
        type          = lifecycle_rule.value.action.type
        storage_class = lookup(lifecycle_rule.value.action, "storage_class", null)
      }
      condition {
        age                   = lookup(lifecycle_rule.value.condition, "age", null)
        created_before        = lookup(lifecycle_rule.value.condition, "created_before", null)
        with_state            = lookup(lifecycle_rule.value.condition, "with_state", null)
        matches_storage_class = lookup(lifecycle_rule.value.condition, "matches_storage_class", null)
        num_newer_versions    = lookup(lifecycle_rule.value.condition, "num_newer_versions", null)
      }
    }
  }
}
EOF

Definisikan seluruh variabel input untuk modul pada berkas variables.tf di dalam direktori modul:

Bash (Cloud Shell) 
cat <<'EOF' > variables.tf
variable "name" {
  description = "The name of the bucket."
  type        = string
}

variable "project_id" {
  description = "The ID of the project to create the bucket in."
  type        = string
}

variable "location" {
  description = "The location of the bucket."
  type        = string
}

variable "storage_class" {
  description = "The Storage Class of the new bucket."
  type        = string
  default     = null
}

variable "labels" {
  description = "A set of key/value label pairs to assign to the bucket."
  type        = map(string)
  default     = null
}

variable "bucket_policy_only" {
  description = "Enables Bucket Policy Only access to a bucket."
  type        = bool
  default     = true
}

variable "versioning" {
  description = "While set to true, versioning is fully enabled for this bucket."
  type        = bool
  default     = true
}

variable "force_destroy" {
  description = "When deleting a bucket, this boolean option will delete all contained objects. If false, Terraform will fail to delete buckets which contain objects."
  type        = bool
  default     = true
}

variable "iam_members" {
  description = "The list of IAM members to grant permissions on the bucket."
  type = list(object({
    role   = string
    member = string
  }))
  default = []
}

variable "retention_policy" {
  description = "Configuration of the bucket's data retention policy for how long objects in the bucket should be retained."
  type = object({
    is_locked        = bool
    retention_period = number
  })
  default = null
}

variable "encryption" {
  description = "A Cloud KMS key that will be used to encrypt objects inserted into this bucket"
  type = object({
    default_kms_key_name = string
  })
  default = null
}

variable "lifecycle_rules" {
  description = "The bucket's Lifecycle Rules configuration."
  type = list(object({
    action = any
    condition = any
  }))
  default = []
}
EOF

Definisikan output untuk modul pada outputs.tf di dalam direktori modul:

Bash (Cloud Shell) 
cat <<'EOF' > outputs.tf
output "bucket" {
  description = "The created storage bucket"
  value       = google_storage_bucket.bucket
}
EOF

Sekarang, kembali ke *Root Module* (direktori Home) untuk mengaitkan modul lokal ini dalam berkas main.tf utama dengan mengarahkan lokasi ke <REGION>:

Bash (Cloud Shell) 
cat <<'EOF' > ~/main.tf
module "gcs-static-website-bucket" {
  source = "./modules/gcs-static-website-bucket"

  name       = var.name
  project_id = var.project_id
  location   = ""

  lifecycle_rules = [{
    action = {
      type = "Delete"
    }
    condition = {
      age        = 365
      with_state = "ANY"
    }
  }]
}
EOF

Buat berkas outputs.tf dan variables.tf pada *Root Module* utama dengan menyertakan Project ID Anda (<PROJECT_ID>):

Bash (Cloud Shell) 
cat <<'EOF' > ~/outputs.tf
output "bucket-name" {
  description = "Bucket names."
  value       = "module.gcs-static-website-bucket.bucket"
}
EOF

cat <<'EOF' > ~/variables.tf
variable "project_id" {
  description = "The ID of the project in which to provision resources."
  type        = string
  default     = ""
}

variable "name" {
  description = "Name of the buckets to create."
  type        = string
  default     = ""
}
EOF

Inisialisasi modul lokal baru tersebut dan eksekusi perintah terraform apply untuk membuat Cloud Storage bucket:

Bash (Cloud Shell) 
cd ~
terraform init
terraform apply -auto-approve

Unduh berkas sampel HTML dan unggah langsung ke Cloud Storage bucket <PROJECT_ID> yang baru saja dibuat:

Penjelasan Konsep: Penggunaan Modul Lokal & Blok Dynamic

Dalam pembuatan modul kustom ini:

  • Local Source (source = "./modules/..."): Terraform membaca modul dari sistem berkas lokal. Setiap perubahan pada berkas modul lokal langsung berlaku saat dijalankan tanpa perlu mengunduh ulang.
  • Dynamic Block: Konstruksi dynamic "lifecycle_rule" digunakan untuk membangun beberapa blok konfigurasi secara kondisional berdasarkan isi list input tanpa perlu menyalin kode secara berulang (*DRY - Don't Repeat Yourself*).
