Task 1: Create a Knowledge Catalog Lake with Two Zones & Two Assets
Task 1
Mengaktifkan API Dataplex/Data Catalog, membuat Dataplex Lake Sales Lake, menambahkan Raw Customer Zone & Curated Customer Zone, serta mengaitkan resource Storage Bucket dan BigQuery Dataset sebagai Asset. Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell:
Bash - Setup Lake, Zones, & Assets
Penjelasan Langkah & Konsep (Task 1)
  • Dataplex Lake (Sales Lake): Unit organisasi utama dalam arsitektur Data Mesh Google Cloud yang mengelompokkan data terdistribusi tanpa perlu memindahkan lokasi penyimpanan aslinya.
  • Raw Zone vs Curated Zone:
    • RAW: Menyimpan data mentah yang belum diproses (dalam kasus ini: Cloud Storage Bucket -customer-online-sessions).
    • CURATED: Menyimpan data yang sudah terstruktur, dibersihkan, dan siap dianalisis (BigQuery Dataset customer_orders).
  • Asset Attachment: Menghubungkan penyimpanan fisik ke dalam zona Dataplex agar metadata, skema, dan tata kelola (governance) dapat dikelola secara terpusat.
Task 2: Create an Aspect Type and Add an Aspect to a Zone
Task 2
Task ini WAJIB dikerjakan secara manual melalui Google Cloud Console.
Panduan Langkah Manual di Cloud Console
  1. Buka Google Cloud Console. Di bilah pencarian atas (atau simbol kaca pembesar jika layar dipersempit), ketik "Knowledge Catalog", lalu klik hasil pencariannya.
  2. Untuk membuat Aspect Type: Di bilah navigasi kiri, di bawah bagian Manage metadata, pilih Metadata types.
  3. Pada tab Aspect types, klik tombol ➕ Create.
  4. Masukkan parameter berikut:
    • Display name: Protected Customer Data Aspect
    • Aspect type ID: *(Biarkan terisi otomatis)*
    • Location: <REGION> *(Sesuai dengan Region Target di atas)*
  5. Pada bagian Template, klik Add Field, lalu isikan:
    • Display Name: Raw Data Flag
    • Type: Enum
    • Klik Add Enum Value, ketik Yes, klik Add Enum Value lagi, ketik no.
    • Klik tombol Done.
  6. Klik tombol Add Field sekali lagi, lalu isikan field kedua:
    • Display Name: Protected Contact Information Flag
    • Type: Enum
    • Klik Add Enum Value, ketik Yes, klik Add Enum Value lagi, ketik no.
    • Klik tombol Done.
  7. Klik tombol Save di bawah untuk membuat Aspect Type tersebut.
  8. Untuk menambahkan Aspect ke Raw Customer Zone:
    • Kembali ke menu Knowledge Catalog.
    • Di bawah bagian Discover di bilah navigasi kiri, pilih Search.
    • Ketik Raw Customer Zone pada kolom pencarian dan jalankan.
    • Klik hasil pencarian teratas bernama raw_customer_zone.
    • Masuk ke tab Details, lalu gulir ke bawah hingga menemukan bagian Aspects.
    • Klik tombol ➕ Add di samping Optional aspects.
    • Pilih Protected Customer Data Aspect dari daftar pilihan yang muncul.
    • Pilih nilai yes untuk kedua kolom field yang tersedia, lalu klik Save.
Konsep & Mengapa Kita Melakukan Ini (Task 2)
  • Apa itu Aspect Type & Aspect? Aspect Type adalah skema kustom tambahan yang kita definisikan untuk memberikan konteks tata kelola (governance), keamanan, atau bisnis pada data di Knowledge Catalog. Mirip seperti membuat tag/label kustom berskala enterprise.
  • Mengapa Menggunakan Tipe Enum (Yes / no)? Membatasi pilihan nilai hanya ke "Yes" atau "no" bertujuan untuk standarisasi tata kelola data. Hal ini meminimalkan kesalahan ketik manual dari tim analis dan memudahkan filtering klasifikasi data sensitif.
  • Tujuan Menempelkan Aspect pada Zona (Zone-level): Menempelkan aspek langsung pada level zona (seperti raw_customer_zone) memastikan seluruh aset data di dalam zona tersebut (dalam hal ini Cloud Storage bucket) secara otomatis ditandai dan mewarisi kebijakan kepatuhan keamanan yang sama secara terpusat.
Task 3: Assign a Knowledge Catalog IAM Role to Another User
Task 3
Memberikan hak akses least-privilege (role roles/dataplex.dataWriter) kepada User 2 pada asset Customer Engagements agar dapat mengunggah file ke Cloud Storage terkait. Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell:
Bash - IAM Assignment
Penjelasan Langkah & Konsep (Task 3)
  • Principle of Least Privilege: Memberikan otorisasi terbatas yang hanya diperlukan oleh pengguna untuk menyelesaikan pekerjaannya tanpa memberikan akses admin berlebih.
  • roles/dataplex.dataWriter: Role khusus Dataplex yang mengizinkan pengguna menulis/mengunggah data pada spesifik asset terkelola tanpa mengakses manajemen konfigurasi lake secara menyeluruh.
Task 4: Create and Upload a Data Quality Specification File
Task 4
Membuat file spesifikasi kualitas data YAML (dq-customer-orders.yaml) dengan aturan NOT NULL (threshold 100%) untuk kolom user_id dan order_id pada tabel ordered_items, lalu mengunggahnya ke bucket -dq-config. Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell:
Bash - Create & Upload DQ Spec
Penjelasan Langkah & Konsep (Task 4)
  • Data Quality Spec (YAML): Berisi pendefinisian aturan (*expectations*) kualitas data. Aturan nonNullExpectation memastikan tidak ada baris data kosong pada Primary Key/Foreign Key kunci.
  • threshold: 1: Berarti tingkat toleransi kelengkapan data (*COMPLETENESS*) adalah 100%. Jika ada 1 saja baris NULL, pemeriksaan kualitas data dianggap gagal (*Failed*).
  • postScanActions: Mengonfigurasi Dataplex agar secara otomatis mengekspor ringkasan hasil pemindaian kualitas data ke tabel BigQuery destination (orders_dq_dataset.results).
Task 5: Define and Run an Auto Data Quality Job
Task 5
Membuat resource pemindaian data (DataScan) kualitas data otomatis customer-orders-data-quality-job pada BigQuery table customer_orders.ordered_items menggunakan file YAML spesifikasi dari Task 4, kemudian langsung mengeksekusinya. Untuk menyelesaikannya, jalankan perintah berikut di Cloud Shell:
Perhatian: Setelah menjalankan perintah di atas, proses pemindaian kualitas data memerlukan waktu sekitar 2 - 5 menit untuk selesai di backend. Nilai di Qwiklabs mungkin tidak langsung terdeteksi hijau. Harap tunggu beberapa saat sambil menekan tombol Check my progress secara berkala.
Bash - Run Data Quality Job
Penjelasan Langkah & Konsep (Task 5)
  • Dataplex DataScan: Fitur serverless milik Google Cloud Dataplex yang menjalankan mesin pemindaian kualitas data dan profiling secara otomatis tanpa perlu mengelola infrastruktur Compute Engine/Dataproc secara manual.
  • Execution Delay: Proses pemindaian Data Quality membutuhkan waktu 2 - 5 menit. Setelah menjalankan perintah, kamu bisa memantau statusnya di Cloud Console menu Dataplex > Data quality.
Catatan Penting: Saat menjalankan Task 5, pemindaian kualitas data memerlukan beberapa menit untuk selesai. Pastikan tombol Check my progress ditekan setelah status job di Console berubah menjadi Succeeded.
