⚙️ Parameter Dinamis Lab

🏖️ Task 1: Create a Knowledge Catalog Lake with Two Zones & Two Assets

Mengaktifkan API Dataplex/Data Catalog, membuat Dataplex Lake Sales Lake, menambahkan Raw Customer Zone & Curated Customer Zone, serta mengaitkan resource Storage Bucket dan BigQuery Dataset sebagai Asset.

🔍 Penjelasan Langkah & Konsep (Task 1)
  • Dataplex Lake (Sales Lake): Unit organisasi utama dalam arsitektur Data Mesh Google Cloud yang mengelompokkan data terdistribusi tanpa perlu memindahkan lokasi penyimpanan aslinya.
  • Raw Zone vs Curated Zone:
    • RAW: Menyimpan data mentah yang belum diproses (dalam kasus ini: Cloud Storage Bucket -customer-online-sessions).
    • CURATED: Menyimpan data yang sudah terstruktur, dibersihkan, dan siap dianalisis (BigQuery Dataset customer_orders).
  • Asset Attachment: Menghubungkan penyimpanan fisik ke dalam zona Dataplex agar metadata, skema, dan tata kelola (governance) dapat dikelola secara terpusat.

🏷️ Task 2: Create an Aspect Type and Add an Aspect to a Zone

Membuat Aspect Type bernama Protected Customer Data Aspect dengan dua field enum (Raw Data Flag & Protected Contact Information Flag) lalu memasangkannya pada Raw Customer Zone.

🔍 Penjelasan Langkah Manual via Cloud Console (Jika gcloud Mengalami Bug)
  1. Buka Dataplex / Knowledge Catalog > Manage Metadata / Aspect types di Console.
  2. Klik Create Aspect Type:
    • Display Name: Protected Customer Data Aspect
    • ID: protected-customer-data-aspect | Region: sesuaikan dengan lab (misal us-west1).
  3. Tambahkan 2 Field bertipe Enumeration:
    • Field 1 ID: raw_data_flag | Display Name: Raw Data Flag | Values: Yes, No
    • Field 2 ID: protected_contact_information_flag | Display Name: Protected Contact Information Flag | Values: Yes, No
  4. Klik Create. Selesai dibuat, buka menu Lakes > Sales Lake > buka zona Raw Customer Zone.
  5. Masuk ke tab Aspects > Klik Add Aspect > Pilih Protected Customer Data Aspect > Set kedua flag ke nilai Yes > Klik Save.

🔐 Task 3: Assign a Knowledge Catalog IAM Role to Another User

Memberikan hak akses least-privilege (role roles/dataplex.dataWriter) kepada User 2 pada asset Customer Engagements agar dapat mengunggah file ke Cloud Storage terkait.

🔍 Penjelasan Langkah & Konsep (Task 3)
  • Principle of Least Privilege: Memberikan otorisasi terbatas yang hanya diperlukan oleh pengguna untuk menyelesaikan pekerjaannya tanpa memberikan akses admin berlebih.
  • roles/dataplex.dataWriter: Role khusus Dataplex yang mengizinkan pengguna menulis/mengunggah data pada spesifik asset terkelola tanpa mengakses manajemen konfigurasi lake secara menyeluruh.

📄 Task 4: Create and Upload a Data Quality Specification File

Membuat file spesifikasi kualitas data YAML (dq-customer-orders.yaml) dengan aturan NOT NULL (threshold 100%) untuk kolom user_id dan order_id pada tabel ordered_items, lalu mengunggahnya ke bucket -dq-config.

🔍 Penjelasan Langkah & Konsep (Task 4)
  • Data Quality Spec (YAML): Berisi pendefinisian aturan (*expectations*) kualitas data. Aturan nonNullExpectation memastikan tidak ada baris data kosong pada Primary Key/Foreign Key kunci.
  • threshold: 1: Berarti tingkat toleransi kelengkapan data (*COMPLETENESS*) adalah 100%. Jika ada 1 saja baris NULL, pemeriksaan kualitas data dianggap gagal (*Failed*).
  • postScanActions: Mengonfigurasi Dataplex agar secara otomatis mengekspor ringkasan hasil pemindaian kualitas data ke tabel BigQuery destination (orders_dq_dataset.results).

📊 Task 5: Define and Run an Auto Data Quality Job

Membuat resource pemindaian data (DataScan) kualitas data otomatis customer-orders-data-quality-job pada BigQuery table customer_orders.ordered_items menggunakan file YAML spesifikasi dari Task 4, kemudian langsung mengeksekusinya.

🔍 Penjelasan Langkah & Konsep (Task 5)
  • Dataplex DataScan: Fitur serverless milik Google Cloud Dataplex yang menjalankan mesin pemindaian kualitas data dan profiling secara otomatis tanpa perlu mengelola infrastruktur Compute Engine/Dataproc secara manual.
  • Execution Delay: Proses pemindaian Data Quality membutuhkan waktu 2 - 5 menit. Setelah menjalankan perintah, kamu bisa memantau statusnya di Cloud Console menu Dataplex > Data quality.
