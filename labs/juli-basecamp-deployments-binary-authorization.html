Gating Deployments with Binary Authorization

Panduan interaktif dan efisien untuk mengonfigurasi Binary Authorization pada Google Kubernetes Engine (GKE) dengan tanda tangan digital KSA/KMS untuk keamanan rantai pasok kontainer.

💡 Referensi & Pelajari Lebih Lanjut: Google Cloud Skills Boost Lab Page

Parameter Lab Anda

Isi variabel dari halaman Qwiklabs Anda di bawah ini agar seluruh perintah terkonfigurasi secara otomatis secara presisi.

Tips: Cari dengan Ctrl+F qwiklabs-gcp- atau lihat di panel kredensial Qwiklabs sebelah kiri.
Tips: Region default yang diberikan oleh Qwiklabs (misal: us-east1).
Tips: Zone lokasi cluster GKE yang ditentukan oleh lab (misal: us-east1-b).
PERSIAPAN Inisialisasi Environment & API Google Cloud

Buka Cloud Shell dari konsol Google Cloud, lalu jalankan perintah berikut untuk mengonfigurasi variabel lingkungan awal serta mengaktifkan seluruh API pendukung yang dibutuhkan.

Bash (Cloud Shell)
Mengapa API ini diaktifkan?
Perintah ini mengaktifkan API krusial untuk keamanan GCP:
  • binaryauthorization.googleapis.com: Kebijakan penegakan keamanan saat deployment kontainer.
  • cloudkms.googleapis.com: Pengelolaan kunci kriptografi penandatanganan.
  • containeranalysis.googleapis.com: Metadata dan penyimpanan catatan (Attestor Note).
TASK 1 Membuat Repository Artifact Registry & Build Sample Image

Buat repositori Docker di Artifact Registry, konfigurasi autentikasi Docker, lalu bangun sampel aplikasi Python Flask menggunakan Cloud Build.

Bash (Cloud Shell)
Konsep Utama Task 1
Aplikasi sederhana ini akan dijadikan sampel image kontainer di Artifact Registry region us-east1 untuk kemudian diuji proses verifikasi Binary Authorization-nya.
Klaim Poin: Create Artifact Registry repository.
TASK 2 Membuat Attestor & Container Analysis Note

Attestor bertanggung jawab memverifikasi keamanan image. Di sini Anda akan membuat Note pada Container Analysis API dan meregistrasikan Attestor vulnz-attestor ke Binary Authorization.

Bash (Cloud Shell)
Memahami Attestor & Note
  • Note: Metadata tempat menyimpan catatan kelayakan image (misal: lolos pemindaian kerentanan).
  • Attestor: Otoritas yang memegang kunci kriptografi untuk menandatangani image. Service account Binary Authorization memerlukan akses viewer pada Note ini.
Klaim Poin: Create an Attestor.
TASK 3 Menambahkan Cryptographic Key via Cloud KMS

Buat Keyring dan pasangan kunci kriptografi asimetris di Cloud KMS, lalu hubungkan kunci publiknya ke vulnz-attestor.

Bash (Cloud Shell)
Klaim Poin: Add a KMS key.
TASK 4 Membuat Signed Attestation Secara Manual

Dapatkan digest image sampel Anda lalu buat Attestation digital secara manual menggunakan kunci KMS yang baru dibuat.

Bash (Cloud Shell)
Apa itu Image Digest & Attestation?
Image digest adalah hash unik immutable (misal: sha256:...). Attestation menghubungkan hash ini dengan tanda tangan digital Attestor untuk membuktikan bahwa versi spesifik kontainer telah disetujui.
TASK 5 Mengonfigurasi Policy & Membuat Cluster GKE
Perhatian Durasi: Pembuatan cluster GKE binauthz membutuhkan waktu estimasi 3 hingga 5 menit. Mohon tunggu dengan sabar hingga proses CLI selesai sebelum melanjutkan ke langkah berikutnya.

Jalankan perintah berikut untuk membuat cluster GKE dengan fitur Binary Authorization aktif, lalu uji coba perubahan policy dari ALWAYS_ALLOW ke ALWAYS_DENY.

Bash (Cloud Shell)
Mekanisme Policy Binary Authorization
Ketika kebijakan diset ke ALWAYS_DENY, Kubernetes Admission Webhook secara otomatis memblokir setiap permintaan deployment baru yang tidak memenuhi kriteria aturan.
Klaim Poin: Create a GKE cluster and update the policies.
TASK 6 Otomatisasi Penandatanganan Image di Pipeline Cloud Build

Konfigurasi role IAM yang diperlukan untuk Cloud Build Service Account, buat Custom Build Step penandatanganan, dan eksekusi pipeline CI/CD otomatis via cloudbuild.yaml.

Bash (Cloud Shell)
Klaim Poin: Add a signing step.
TASK 7 Menjalankan Kontainer Tertanda Tangan (Authorized Image)

Perbarui kebijakan Binary Authorization pada GKE agar **mewajibkan adanya tanda tangan** (REQUIRE_ATTESTATION) dari vulnz-attestor, lalu lakukan deploy image yang valid (:good).

Bash (Cloud Shell)
Klaim Poin: Deploy a signed image.
TASK 8 Verifikasi Pemblokiran Image Tanpa Tanda Tangan (Unsigned)

Uji keandalan sistem keamanan dengan membuat image tanpa tanda tangan digital (:bad) dan pastikan deployment ke GKE **ditolak secara otomatis** oleh Binary Authorization.

Bash (Cloud Shell)
Klaim Poin: Deploy an unsigned image.
