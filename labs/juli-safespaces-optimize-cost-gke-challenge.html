🚀 Panduan Qwiklabs: Optimize Costs for Google Kubernetes Engine: Challenge Lab

Selesaikan deployment OnlineBoutique di GKE secara otomatis, cepat, dan terhindar dari pemborosan biaya (Cost Optimization) dengan panduan skrip presisi ini.

⚙️ Konfigurasi Variabel Lab

Isi variabel di bawah secara teliti. Seluruh perintah di bawah akan otomatis terpasang dengan nilai ini.

Project ID dari panel kredensial sebelah kiri Qwiklabs.
Tekan Ctrl+F lalu cari Zone di paragraf Challenge scenario atau Task 1 (misal: us-east1-d).
Cari Cluster Name di dalam tabel kredensial sebelah kiri Qwiklabs (misal: onlineboutique-cluster-552).
Cari Pool Name di dalam tabel kredensial sebelah kiri Qwiklabs (misal: optimized-pool-4450).
Cari angka Max Replicas di dalam tabel kredensial sebelah kiri Qwiklabs (biasanya 10).

Task 1. Create a cluster and deploy your app

Buat cluster GKE kecil dengan 2 nodes di zona <ZONE>, lalu deploy aplikasi OnlineBoutique ke dalam namespace dev.

Mengapa menggunakan machine type e2-standard-2?
Ini adalah langkah awal (baseline) sebelum kita melakukan optimasi biaya. Kita membuat cluster yang cukup standar (2 vCPU, 8GB RAM) agar aplikasi bisa berjalan dulu, lalu di Task 2 kita akan memigrasikannya ke pool yang lebih murah dan efisien.
⚠️ Peringatan: Kode di bawah mengandung parameter dinamis. Silakan isi form parameter di atas terlebih dahulu agar terisi otomatis.

Task 2. Migrate to an optimized node pool

Kita akan membuat node pool baru bernama <POOL_NAME> menggunakan mesin kustom (custom-2-3584) yang memiliki RAM lebih kecil untuk menghemat biaya, lalu memigrasikan workload (cordon & drain).

Apa itu Cordon dan Drain?
  • kubectl cordon: Menandai node lama agar tidak menerima pod baru lagi.
  • kubectl drain: Mengusir pod yang sedang berjalan di node lama secara perlahan agar pindah ke node pool baru yang baru saja kita buat.
