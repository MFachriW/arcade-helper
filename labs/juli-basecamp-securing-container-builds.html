Securing Container Builds

Panduan interaktif pengelolaan repositori paket Java Maven menggunakan Artifact Registry Google Cloud dengan mode Standard, Remote Caching, dan Virtual Repositories.

Task 1. Standard Repositories
Task 1

Buat Standard Repository berformat Maven bernama container-dev-java-repo di region us-central1 untuk menyimpan dan membagikan paket Java privat internal organisasi Anda.

Penjelasan Teknis: Mode Standard Repository

Standard Repository adalah mode repositori bawaan di Artifact Registry. Mode ini bertindak sebagai penyimpanan privat tempat Anda mempublikasikan (*publish/deploy*) dependensi buatan internal tim developer agar dapat diunduh oleh proyek atau aplikasi lain.

Task 2. Configure Maven for Artifact Registry
Task 2

Konfigurasikan berkas pom.xml pada proyek Java agar mengenali Artifact Registry menggunakan ekstensi autentikasi `artifactregistry-maven-wagon`, lalu unggah (*deploy*) artefak `hello-world`.

Penjelasan Otomatisasi & Fungsi Wagons
  • Sistem Otomatis: Perintah Python di bawah digunakan untuk menyisipkan blok konfigurasi Maven (<distributionManagement>, <repositories>, dan <build>) ke dalam pom.xml secara presisi tanpa perlu melakukan penyuntingan manual via Cloud Shell Editor.
  • artifactregistry-maven-wagon: Ekstensi ini memungkinkan Apache Maven melakukan otentikasi aman menggunakan token OAuth2 bawaan dari GCP Service Account/gcloud CLI saat berkomunikasi dengan endpoint artifactregistry://.
Catatan Durasi: Proses mvn deploy mengunduh plugin Maven wagon dan mengompilasi artefak Java ke Artifact Registry (membutuhkan waktu sekitar 1 hingga 3 menit). Harap bersabar tunggu hingga terminal selesai memproses dan kembali ke prompt Cloud Shell!

Task 3. Remote Repositories
Task 3

Buat Remote Repository bernama maven-central-cache yang berfungsi sebagai *proxy cache* untuk Maven Central publik guna meningkatkan keandalan build dan kecepatan unduh dependensi pihak ketiga.

Penjelasan Teknis: Mode Remote Repository

Remote Repository bertindak sebagai lapisan penyangga (*caching proxy*) terhadap repositori eksternal publik seperti Maven Central. Ketika build meminta dependensi publik, Artifact Registry akan mengunduh dan menyimpannya di cache GCP sehingga proses build berikutnya lebih cepat dan tidak terpengaruh jika repositori publik mengalami gangguan (*downtime*).

Task 4. Virtual Repositories
Task 4

Buat Virtual Repository bernama virtual-maven-repo yang menggabungkan beberapa repositori hulu (*upstream*) ke dalam satu URL tunggal dengan kebijakan prioritas guna mencegah serangan *Dependency Confusion*.

Penjelasan Teknis: Mode Virtual Repository & Security

Virtual Repository memberikan satu titik akses tunggal (*single endpoint*) untuk beberapa repositori hulu (Standard privat & Remote cache). Dengan menetapkan prioritas tinggi pada repositori privat (priority 100) dibanding cache publik (priority 80), Artifact Registry memastikan bahwa paket privat internal selalu diutamakan sehingga mencegah *Dependency Confusion Attack*.
