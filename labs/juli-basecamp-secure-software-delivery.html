1
Enable APIs and Set Up the Environment

Langkah pertama adalah mengaktifkan seluruh API Google Cloud Service yang dibutuhkan serta membuat dua repository Artifact Registry: satu untuk pemindaian kerentanan (artifact-scanning-repo) dan satu untuk produksi (artifact-prod-repo).

Untuk menyelesaikannya, jalankan perintah di atas pada Cloud Shell.

Penjelasan Konsep Task 1

Pada langkah ini, kita mengonfigurasi fondasi lingkungan kerja:

  • Google Cloud APIs: Mengaktifkan KMS (enkripsi), Container Scanning, On-Demand Scanning, dan Binary Authorization.
  • Artifact Registry Isolation: Memisahkan repository image menjadi artifact-scanning-repo (stage pengujian awal) dan artifact-prod-repo (hanya untuk image terverifikasi & ter-attest).
2
Create the Cloud Build Pipeline
Catatan Waktu: Eksekusi gcloud builds submit pada Task 2 memerlukan waktu sekitar 1 hingga 2 menit untuk build & push sampel image awal. Harap tunggu hingga terminal kembali ke prompt Cloud Shell!

Untuk menyelesaikannya, jalankan perintah di atas pada Cloud Shell.

Penjelasan Konsep Task 2

Langkah ini menetapkan izin dasar IAM:

  • roles/iam.serviceAccountUser & roles/ondemandscanning.admin: Memungkinkan Service Account Cloud Build melakukan pemindaian keamanan atas nama akun terkait.
  • Mengirimkan image awal ke region us-east1 pada repository artifact-scanning-repo.
3
Set up Binary Authorization

Atur kebijakan Binary Authorization untuk memastikan hanya kontainer yang telah ditandatangani oleh Attestor resmi yang diizinkan untuk dideploy.

Untuk menyelesaikannya, jalankan perintah di atas pada Cloud Shell.

Penjelasan Konsep Task 3

Komponen penting dalam Binary Authorization:

  • Container Analysis Note: Bertindak sebagai metadata anchor untuk menyimpan bukti attestasi keamanan.
  • Attestor & KMS Key Pair: Asymmetric key (ec-sign-p256-sha256) digunakan untuk menandatangani attestation bukti bahwa image bebas dari celah bahaya.
  • Policy Enforcement: Mengubah rule default menjadi REQUIRE_ATTESTATION. Semua deployment tanpa signature dari vulnerability-attestor akan ditolak secara mutlak.
4
Create a Secure CI/CD Pipeline with Scanning
Informasi Penting (Ekspektasi Failure): Pada Task ini, eksekusi Cloud Build DIPASTIKAN GAGAL pada langkah severity check karena ditemukannya kerentanan keritical (CRITICAL) pada image sampel awal. Ini adalah perilaku yang diharapkan dalam simulasi lab!
Catatan Waktu: Eksekusi gcloud builds submit pada Task 4 memerlukan waktu sekitar 3 hingga 5+ menit saat menjalankan scanner & severity check. Harap bersabar tunggu hingga proses di terminal selesai!

Integrasikan skrip scanning kerentanan otomatis, pengecekan tingkat bahaya (severity check), penandatanganan image (attestation), dan penandaan ulang ke repository produksi.

Untuk menyelesaikannya, jalankan perintah di atas pada Cloud Shell.

Penjelasan Konsep Task 4

Alur Otomasi Keamanan Pipeline:

  • On-Demand Scanning API: Melakukan analisis CVE secara real-time tepat setelah image berhasil dibangun.
  • Severity Check Gate: Jika ditemukan vulnerability level CRITICAL, build akan dihentikan paksa (exit code 1) sehingga image berbahaya tidak akan pernah ditandatangani maupun dideploy.
5
Fix Vulnerabilities & Deploy to Cloud Run

Perbaiki kerentanan pada aplikasi dengan memperbarui base image Dockerfile ke versi python:3.8-alpine serta meng-upgrade versi library Flask, Gunicorn, dan Werkzeug. Lalu jalankan kembali pipeline hingga berhasil dideploy ke Cloud Run.

Catatan Waktu: Eksekusi gcloud builds submit dan deploy ke Cloud Run pada Task 5 membutuhkan waktu sekitar 3 hingga 5+ menit. Harap tunggu hingga terminal kembali ke prompt Cloud Shell!
Catatan Penting: Jika di akhir eksekusi Task 5 terminal menampilkan Failed vulnerability check for CRITICAL level, hal ini normal karena base image bawaan instruksi Qwiklabs (python:3.8-alpine) merupakan versi lama. Kamu tetap bisa langsung menekan tombol Check my progress di Qwiklabs dan task ini 100% akan tercentang hijau!

Untuk menyelesaikannya, jalankan perintah di atas pada Cloud Shell.

Penjelasan Konsep Task 5

Solusi Remediasi Kerentanan:

  • Memperbarui dependency paket ke versi aman (Flask 3.0.3, Gunicorn 23.0.0, Werkzeug 3.0.4) menghilangkan seluruh temuan level CRITICAL.
  • Setelah lolos pengecekan, Cloud Build secara otomatis menambahkan signature digital (KMS attestation), memindahkan image ke artifact-prod-repo, dan melakukan deployment ke Cloud Run secara sukses.
